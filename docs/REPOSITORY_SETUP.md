## Политика изменений

1. Изменение ADR со статусом APPROVED требует нового согласования владельца; нельзя молча объявлять DRAFT утверждённым.
2. Issue для разработки создаётся только после закрытия соответствующих зависимостей M0.
3. Проект не должен реагировать автоматическими coding-триггерами на design Issues.
4. Реальные токены, state и старые Python DevOrchestrator файлы сюда не переносить.
5. Для будущего кода использовать reviewable PR, чёткий scope и проверяемый Definition of Done.

## Проверка

Актуальное содержимое и Issues проверяются непосредственно в GitHub. Эти документы описывают согласованный процесс проектирования, **не являются разрешением на исполнение агентов или публикацию**.
