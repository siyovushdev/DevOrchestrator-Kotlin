# ADR-003 — Trust boundary первого Native PERSONAL MVP

**Статус: APPROVED (owner, 2026-10-17).**  
**Область:** только разрешённый низкорисковый PERSONAL тестовый репозиторий; WORK/1МТ и секретные проекты **вне допуска**.  
**Связано:** [S-04](ADR-003-MVP-native-cli-decision.md), [ADR-001](ADR-001-project-registry.md), [ADR-002](ADR-002-lifecycle-DRAFT.md).

## Решение

1. Для первого работающего MVP Kotlin запускает уже установленный Codex CLI через **`codex exec`**, без Docker/microVM, без дополнительного Linux UID, без самодельного sandbox engine и каскадов временных разрешений.
2. Отдельный temporary clone/worktree с закреплённым base SHA защищает **исходный checkout от прямых изменений**, но **не изолирует файлы и credentials от чтения** при запуске под тем же Linux UID.
3. Использовать штатный native Codex `workspace-write` sandbox; не запускать на хосте в bypass/`danger-full-access` mode. Исполнение, конфигурация модели и завершаемые процессы проверяются реальным коротким smoke перед первым workflow.
4. Controller допускает только заранее явно зарегистрированные PERSONAL тестовые repo ID; неизвестное и WORK — DENY. Публичный GitHub Issue не авторизует выполнение.
5. Кодинг и Review — отдельные попытки, Review проверяет frozen candidate, не меняет публикуемые файлы. В Publisher отдельные роли/команды и durable effects — **логическая**, не ОС-изоляция.
6. **Критичный риск:** Codex с текущим UID может получить доступ к файлам `HOME`, git credential helper или broader GitHub tokens, если они доступны этому UID. Не объявлять иначе. До реального agent run проверить наличие рабочих токенов и обеспечить **отсутствие достижимых ценных секретов или настоящую изоляцию**. Если доказать это нельзя — **не выполнять автономный native agent**.
7. Publisher создаёт только Draft PR в конкретном личном тестовом repo, после точных checks tree/ref/Review и read-after-write. Никакого автоматического Merge. Уровень токена GitHub и фактическая граница запуска подлежат проверке на M2/M3; broad production credentials недопустимы.
8. В случае `UNKNOWN`/crash — ADR-002 recovery, не повторять процессы/эффекты вслепую. Сроки очистки — ADR-002/R-05.

## Отложенное усиление

Ранее согласованная Docker Sandboxes microVM [S-01](ADR-003-security-runtime-DRAFT.md) и S-02 остаются **архивным проектом усиленной изоляции**, не частью реализации первого MVP. Их утверждение как исходной стратегии **заменено S-04 для первого MVP**; возврат возможен только отдельным решением Owner, без автоматического ослабления безопасности.

## Проверка готовности перед исполнением

- Native `codex exec` работает headless с доступной моделью, пишет в disposable PERSONAL worktree и оставляет diff.
- Выход, cleanup, отказ в опасном host-bypass и конфигурация evidence проверены.
- Credential exposure и scope реальных GitHub полномочий проверены. При неоднозначности выполнение блокируется.
- Публикацию реального Draft PR проверяем на M3, а не объявляем выполненной по этому ADR.

**Утверждённое архитектурное решение — не доказательство того, что runtime уже запущен или безопасен на WORK.**
