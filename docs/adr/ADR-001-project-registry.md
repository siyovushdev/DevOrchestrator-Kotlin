# ADR-001 — Project Registry и Project-Level Execution Policy

**Статус:** APPROVED (согласовано владельцем в ChatGPT, 2026-10-17)  
**Контекст:** DevOrchestrator Kotlin/JVM, M0

## Контекст

DevOrchestrator должен управлять несколькими личными и рабочими репозиториями без смешения полномочий. Название проекта, GitHub username и текст Issue не могут сами по себе определять, разрешён ли автоматический запуск.

## Решение

1. **Единый Project Registry.** Каждый проект регистрируется один раз доверенным владельцем и получает собственную политику выполнения и безопасности.
2. Запись проекта содержит: уникальный Project ID; точный GitHub repository и стабильный repository ID; тип `PERSONAL`/`WORK`; разрешённый workspace root; Coding agent и независимый Reviewer; execution/publication policy; ресурсные и временные лимиты.
3. **PERSONAL:** для явно разрешённого проекта автоматически выполняются `GitHub Issue → Coding → Tests → Independent Review → Draft PR`, с ограниченным числом correction attempts. Merge — только владелец. PERSONAL сам по себе **не** даёт автоматического разрешения: требуется отдельный явный флаг/политика проекта.
4. **WORK (в том числе 1МТ):** старт только после Owner GO; публикация требует отдельного разрешения. Полномочия PERSONAL не наследуются.
5. **Default DENY:** неизвестный проект, неизвестный repo ID, несоответствующий workspace и действия вне политики блокируются до побочных эффектов.
6. Политики может менять только авторизованный владелец; изменения имеют аудит и версию. Issue и Coding/Review agent не могут менять тип/режим или выдавать себе права.
7. Android-пульт позднее использует тот же серверный реестр и защищённое API; телефон не является отдельным источником истины.

## Примеры применения (не зарегистрированные реальные политики)

| Проект | Тип | Пример режима |
|---|---|---|
| MyRtcShutdown | PERSONAL | Автоматически, если явно включено в registry |
| Firefly Voice Assistant | PERSONAL | Автоматически в разрешённых границах |
| 1MT.adbus.android | WORK | Только Owner GO на запуск/публикацию |

## Последствия

- **Плюс:** единый оркестратор, разные границы безопасности, расширяемость на десятки проектов.
- **Стоимость:** нужны валидация registry, управление разрешениями, миграции и аудит.
- **Запрещённый shortcut:** считать любой репозиторий `siyovushdev/*` личным и автоматически разрешённым.

## Критерий реализации

Уверенно связанная с зарегистрированным repo ID Issue получает только разрешённые проектом операции. Неизвестная/подменённая Issue не запускает агента и не создаёт внешних эффектов. Изменение политики доступно лишь владельцу и оставляет запись в истории.

## Не решено этим ADR

Task lifecycle/recovery (ADR-002), криптографическая/операционная модель доверенного Owner, конкретная система sandbox, механизм GitHub-авторизации, спецификация Android API. Всё это согласуется отдельно.
