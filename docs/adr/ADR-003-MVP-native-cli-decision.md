# ADR-003 / S-04 — Native Codex CLI для первого MVP (поправка к S-01/S-02)

**Статус: APPROVED владельцем 2026-10-17 для Native PERSONAL test MVP.** Итоговый ограниченный ADR — [ADR-003 Native](ADR-003-native-personal-mvp.md). WORK и повышенная изоляция вне допуска. **Код ещё не запущен.**

## Решение

В первом серверном MVP использовать **уже установленный на WORK Codex CLI** непосредственно из Kotlin/JVM через управляемый дочерний процесс (`ProcessBuilder`/эквивалент). **Не устанавливать Docker, microVM, отдельный Linux account, systemd sandbox и собственный permission engine** для получения первого реального результата.

**Это supersession ранее одобренного выбора Docker Sandboxes (S-01) именно для первого MVP.** Docker/microVM, Gate S0 для VM и VM-специфические части S-02 откладываются, не удаляются. Общие цели S-02 — чистая рабочая копия, контролируемый diff/evidence, независимый Review и отдельный Publisher — сохраняются. Но на том же Unix UID это **не гарантирует** защиты от чтения чужих файлов и локальных credential stores: не утверждать обратное.

## Минимальная цепочка MVP

`GitHub Issue → Project allowlist → изолированный временный git worktree/clone личного тестового репозитория → codex exec (Coding) → Tests → отдельный codex exec (Review) → только проверенный Draft PR`.

- **Та же учётная запись пользователя и существующая авторизация Codex CLI:** не переносить токены и не создавать новую auth-инфраструктуру. Kotlin должен работать с теми же PATH/HOME/CODEX_HOME, что и успешная терминальная команда; конфигурация, разрешения и CLI флаги сверяются для каждой конкретной установленной версии.
- **Без интерактивного терминала:** использовать поддерживаемый CLI режим `codex exec`, а не запуск интерактивного `codex` с имитацией нажатий в TUI. Стандартный Codex sandbox `workspace-write`, без `--dangerously-bypass-approvals-and-sandbox` / `danger-full-access` на хосте. `--ask-for-approval never` допустим **только при реально работающем sandbox**, после короткого smoke.
- **Папка отдельная, но не security boundary:** изолированный Git worktree защищает главный checkout от прямых изменений, однако процесс с текущим UID может читать файлы, доступные этому UID. Для первого MVP допускаются **только явно зарегистрированные не секретные PERSONAL тестовые репозитории**. WORK / 1МТ не запускать автономно в таком профиле.
- **Review отдельно:** новая non-interactive сессия, зафиксированный commit/tree/diff. Reviewer не публикует и не перезаписывает решение Coding; его изменения не включаются в результат.
- **Публикация:** только trusted Kotlin Publisher после успешного Review. Поскольку Publisher/Agent под одним Unix UID — **реального OS-разделения секретов нет**, даже если токен не передан через env. Для первого E2E использовать строго ограниченные credentials **только на отдельный PERSONAL тестовый repo**, которые не дают доступ к рабочим проектам. Для WORK или серьёзных проектов понадобится отдельная системная граница/дополнительное согласование; считать native MVP защищённым на уровне microVM запрещено.
- **Agent Catalog:** не хардкодить модель/роль в WorkflowEngine; после первого рабочего Codex E2E поддержать другие адаптеры/модели/effort по FR-13–FR-18.

## Короткий smoke вместо VM Gate S0

1. Проверить `codex --version`, `codex login status`, доступный `codex exec --help` и `codex exec` именно в non-interactive режиме; не считать работающую TUI доказательством работы headless.
2. Создать чистый **одноразовый PERSONAL git repo/worktree**, запустить одну задачу записи тестового файла и проверить **реальный файл и Git diff**, а не только exit code или текст Codex.
3. Отдельным `codex exec` выполнить независимый read-only review на pinned tree. Подтвердить, что Review не меняет кандидат.
4. Проверить, что Codex не пишет за пределами workspace в выбранном native sandbox, доступность нужных для MVP команд и зависимостей; если требуемое действие заблокировано, диагностировать **один раз**, а не открывать список обходов.
5. Проверить timeout/stop и отсутствие подтверждённых работающих дочерних процессов. Если состояние неизвестно — ADR-002/NEEDS_OWNER, не слепой retry.

**PASS** даёт основание реализовать Native CLI Adapter после M0. **FAIL** означает конкретный blocker с одной целевой проверкой; нельзя разрешать host `--yolo` для обхода. Никакого Docker Gate S0 на пути первого Draft PR.

## Принципы скорости

- **Первый E2E раньше расширения инфраструктуры.** Не начинать Docker, multi-machine, Android, AI Agent Selector или второго агента до реального Coding → Review → Draft PR.
- Только необходимые статусы/SQLite intents, no blind retries по ADR-002. Без второй параллельной системы флагов и временных разрешений.
- Возможности Codex из коробки использовать как есть; Kotlin только координирует запуск, проверку, GitHub, результат.
- Разрешения WORK и цели изоляции из ADR-001/S-02 не отменены, но native запуск не удовлетворяет им полностью: WORK по этому профилю **запрещён**.

## Отложено

Ранее утверждённый Docker Sandboxes S-01 и документ S-02 остаются **историей архитектурных решений и целевым усиленным профилем**; их VM-специфические предположения, в том числе "агент не может читать host secrets", **не применяются** к native MVP. Вернуться к microVM только при появлении практической необходимости и отдельном решении владельца.

**M0 утверждён Owner для перехода к M1.** Это разрешает разработку нового Kotlin-проекта, но не утверждает фактическую защиту среды, не разрешает WORK/1МТ execution и не подтверждает E2E. Smoke, credential preflight и публикация Draft PR — проверки будущих M2/M3.
