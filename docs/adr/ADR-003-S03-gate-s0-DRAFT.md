# ADR-003 / S-03 — Короткий Gate S0 перед разработкой AgentRunner

> **DEFERRED:** это план проверки **Docker microVM**, а не обязательный Gate для первого MVP после [S-04 native CLI](ADR-003-MVP-native-cli-decision.md). Для первого MVP достаточно короткого headless `codex exec` smoke в disposable PERSONAL repo. Никакого S0 VM или установки Docker на пути к первому Draft PR.


**Статус: DRAFT — не согласовано.** 2026-10-17. Этап M0, Issue #3.
**Основа:** S-01/S-02 (APPROVED), ADR-001/ADR-002 (APPROVED). Никакие runtime-тесты на WORK ещё не выполнялись.

## Цель

Не повторить старый DevOrchestrator: сначала одно короткое реальное испытание Codex в Docker Sandboxes microVM, затем — реализация Kotlin AgentRunner. Без многоуровневого самодельного sandbox и запросов на каждую команду.

## PASS, FIXABLE, BLOCKED

- **PASS:** реальные проверки и отрицательные тесты выполнены; версии/runtime/profile зафиксированы без хранения секретов. Можно планировать интеграцию после согласования M0.
- **FIXABLE:** один конкретный совместимый дефект конфигурации с понятным исправлением. Предлагается одна целевая правка и один повтор полного S0.
- **BLOCKED:** S0 повторно не прошёл, граница VM/секретов нарушена или нет достоверного cleanup. Не ослаблять host/VM безопасность; не делать новый стек обходов. Передать решение владельцу: выбрать поддерживаемую альтернативу отдельным ADR.

## Не создавать новую permission-систему

1. Один базовый sandbox runtime для разных агентов: Docker Sandboxes microVM. Не наслаивать ещё несколько конфликтующих механизмов безопасности.
2. Полный Gate S0 выполняется при интеграции и после значимых изменений runtime/VM boundary, **не перед каждой GitHub Issue**.
3. Перед каждой задачей только короткие проверки project identity/policy, model capabilities, состояния ресурса; для заранее разрешённого PERSONAL workflow без ручных подтверждений каждой команды.
4. Не копировать в агент реальные host credentials. Publisher остаётся вне VM и делает только разрешённый Draft PR.
5. S0 проверяет основу, но не заменяет финальный E2E: реальная GitHub Issue -> Coding -> Review -> Draft PR (M3).

## Требует согласования владельца

- Утвердить S0 как одноразовый практический Gate, а не бесконечный самостоятельный проект.
- Определить минимальные лимиты ресурсов VM/диска и правила cleanup перед экспериментом.
- Утвердить порядок остановки и отдельного решения при BLOCKED после одного диагностического цикла.
- Реальный запуск S0 на WORK разрешать отдельно после M0 или при специально ограниченном Owner approval.

**Статус S-03: DRAFT.** Это план, а не свидетельство, что Docker Sandboxes установлен или проверен.
